DB 视图导出工具 · 使用说明书
================================================================================
版本：通用版 v1.0        生成时间：2026-10-30 21:10
适用系统：Windows 10 / 11（64 位）
适用对象：任意 SQLite 数据库（.db / .sqlite / .db3）
是否需要安装 Python：不需要（exe 已自带运行环境）


================================================================================
一、这是什么
================================================================================
把 SQLite 数据库里的视图（或表）逐个导出成 Excel 文件的小工具。

典型用途：
  · 数据库里的视图在图形工具里打不开、显示错位、列宽乱掉；
  · 想把视图数据发给别人看，但对方没有数据库工具；
  · 想快速核对某个视图有多少行、有哪些列。

它只做一件事：读数据库 → 写 Excel。不做分析、不做判断、不联网。


================================================================================
二、目录内容
================================================================================
  DB视图导出.exe     主程序，双击即用（约 32 MB，已自带 Python 与 Excel 库）
  DB视图导出.bat     启动入口（内容为 ASCII，避免中文路径解析问题）
  调试运行.bat       出问题时用它：会停住窗口并显示退出码
  使用说明.txt       本文件
  db_view_export.py  源码（想改逻辑或审计时看，不运行它也行）

  ★ 整个文件夹可以放在任何位置，也可以整个删掉，不影响其他程序。


================================================================================
三、快速开始（三步）
================================================================================
  1) 双击 DB视图导出.bat（或直接双击 DB视图导出.exe）
  2) 把 .db 文件拖进黑窗口，回车
       · 也可以拖 .lnk 快捷方式
       · 也可以拖一个文件夹（自动选里面最新的 .db）
       · 也可以直接粘贴路径
  3) 屏幕列出库里所有视图，输入序号：
         0 或直接回车  = 全部导出（按行数从小到大）
         1、2、3…      = 只导那一个
  4) 完成后桌面出现 <库名>-<时间戳>\ 文件夹
  5) 结束会问"还要导出别的库吗？"，输 n 退出


================================================================================
四、导出结果长什么样
================================================================================
  Desktop\blacklist-20261030-211500\
      清单.txt              每个对象多少行、多少列；失败的写原因
      玩家总览.xlsx          一个视图一个文件
      大致统计.xlsx
      ...

  Excel 文件的处理：
    · 表头加粗、冻结首行（往下滚时字段名始终可见）
    · 列宽按表头 + 前 200 行内容自动计算（上限 60 字符）
    · 单元格超过 32000 字符会截断，并在末尾标 "…（已截断）"
      （Excel 单元格硬上限 32767，不截断会写坏文件）
    · 二进制列（BLOB）转成十六进制字符串
    · 文件名里的 \ / : * ? " < > | 会被替换成下划线

  如果桌面写不进去（被"受控文件夹访问"拦住）：
    自动依次尝试 文档 → 当前目录 → 临时目录，并在屏幕上告诉你落在哪。


================================================================================
五、命令行用法（可选，批处理/脚本用）
================================================================================
  DB视图导出.exe --db "D:\x.db" --yes                      全部导出（xlsx）
  DB视图导出.exe --db "D:\x.db" --yes --format csv          导出 CSV
  DB视图导出.exe --db "D:\x.db" --objects tables --yes      导出表（不导视图）
  DB视图导出.exe --db "D:\x.db" --objects all --yes         视图 + 表
  DB视图导出.exe --db "D:\x.db" --no-count --yes            跳过预统计，更快
  DB视图导出.exe --db "D:\x.db" --check --yes               先跑完整性检查
  DB视图导出.exe --db "D:\x.db" --optimize --yes            临时副本上优化后导出

  参数说明：
    --db PATH             数据库路径；不给就进交互模式
    --objects views|tables|all   导出对象类型，默认 views
    --format xlsx|csv     默认 xlsx
    --yes                 不交互、全部导出
    --no-count            跳过 COUNT(*)，进度显示"已写 N 行"
    --check               先执行 PRAGMA quick_check（大库较慢，默认不做）
    --optimize            在临时副本上建索引 + ANALYZE 后导出（不改原库）
    --optimize-inplace    直接改给定文件（需输 YES，详见第六节）


================================================================================
六、两种"优化"模式
================================================================================
为什么需要优化：
  有些视图很重（多表关联 + 分组 + 拼接），一条 SELECT 可能几十秒才吐第一行。
  建索引、让 SQLite 统计信息更准，可以明显加快。

模式 A：--optimize（推荐，默认不改原文件）
  流程：
    1. 检查临时目录空间（需要 库大小 × 1.25 + 64 MB）
       空间不够会问你：
           1) 跳过优化，直接用这个库导出（不复制，较慢）
           2) 取消，换个库或清理临时目录后再试
    2. 用 SQLite backup API 做一份一致性副本到 %TEMP%
       库 ≥ 1 GB 时显示复制进度：
           复制中  45.3%  170 MB/375 MB  已用 0:03  剩余 ~0:04 （输 n 取消）
       复制中按 n 可立即取消：半成品会删掉，然后改用原库只读导出
       （原库不会被删除、不会被修改）
       库 < 1 GB 时不显示进度（复制只要一两秒），也不响应 n
    3. 在副本上建索引 ix_exp_lookup + 执行 ANALYZE
    4. 从副本导出
    5. 删除副本
  结果：原文件全程只读，导出结束后临时目录不残留。

模式 B：--optimize-inplace（会改文件，慎用）
  直接在你给的那个 .db 上建索引 + ANALYZE，导出结束再删掉自己建的索引。
  · 必须输入大写 YES 才会执行
  · 请只对**备份副本**使用，不要对正在运行的主库使用
  · 中途强制结束可能残留索引（不影响数据；再跑一次会自动复用）

交互模式下，库超过 30 MB 时会主动问一句：
  这个库有 375 MB，要不要在临时副本上建索引/统计以加速？（不改原文件）(Y/n)


================================================================================
七、安全设计（它为什么不会弄坏你的库）
================================================================================
  1. 默认用 mode=ro&immutable=1 只读打开：不写原库，也不产生 -wal/-shm
  2. 数行数用独立连接，同样只读，不跨线程共享连接
  3. 万一生成了 -wal/-shm，按"打开前是否存在"的差值只删自己新建的，
     用户原有的文件一律不动
  4. 优化副本用完即删；取消复制时半成品也删
  5. 单个视图失败不影响其它视图，失败原因写进 清单.txt
  6. 出错时 traceback 写到 %TEMP%\DB视图导出-错误.txt 和桌面


================================================================================
八、边界与已知限制
================================================================================
  · 不支持加密库（SQLCipher 等）
  · 不支持"程序运行中直接复制出来的 .db"——WAL 没合并会报
    database disk image is malformed，请用主程序的备份功能重新做副本
  · 库 ≥ 1 GB 才有复制进度；更小的库复制很快，没有进度条
  · 非交互模式（--yes / 管道输入）不会响应 n，也不会弹空间选择框：
    空间不足时自动按"跳过优化"处理
  · 超大表（几百万行）导出会很慢且 Excel 有 104 万行上限，建议先用
    --no-count 试跑，或只导视图

九、常见问题
================================================================================
  Q: 双击一闪就没了？
  A: 用 调试运行.bat 启动，它会停住并显示 [exit code]。
     错误详情在 %TEMP%\DB视图导出-错误.txt 和桌面。

  Q: 提示打不开数据库 / unable to open database file？
  A: 文件可能在桌面或文档里，被 Windows"受控文件夹访问"拦住读写。
     把库复制到 D:\ 等位置，或把本程序加入白名单：
     Windows 安全中心 → 病毒和威胁防护 → 管理勒索软件防护 →
     受控文件夹访问 → 允许应用。

  Q: 杀毒软件报毒？
  A: PyInstaller 打包的 exe 常被误报，加入白名单即可。
     源码 db_view_export.py 就在旁边，可自行审计。

  Q: 某些列显示不全 / 很窄？
  A: 列宽按内容估算且上限 60 字符；超长文本请点单元格在编辑栏查看。

  Q: 行数显示"未知"？
  A: 该视图 5 秒内没数完（太重），已跳过统计，不影响导出。
     想加速可加 --optimize。
